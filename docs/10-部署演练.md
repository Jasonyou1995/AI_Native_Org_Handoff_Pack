# 10 · 部署演练

本演练只使用合成数据，目标是建立可重复的安装、检查、使用和关闭流程。不是向公网部署的授权，也不是生产验收证明。不要在未完成[上线门槛](09-生产验收与运维.md)前导入业务资料。

个人、大学、企业及其他组织正常内部使用免费，包括内部生产、研究、教学和评估。软件本身对外商业化，例如出售访问、付费托管或捆绑商业产品，须另行许可。一般学费不等于本工具专项访问费。见[商业授权](商业授权.md)。

## A. 获取并准备

1. 从项目仓库取得源码，或解压收到的交付包。若这次改动尚未推送到上游，以交付包为准。核对来源和提交/文件摘要。
2. 安装并启动 Docker Engine/Desktop 与 Compose。在项目根目录运行 `docker version`、`docker compose version`。安装方式以操作系统对应的 [Docker 官方文档](https://docs.docker.com/get-started/get-docker/) 为准。
3. `cp .env.example .env`，用可信密码生成器生成至少 32 字符的随机 `GATEWAY_TOKEN`，替换示例。不要复用账户密码，不要记录到 Git。保持 `CLOUD_ENABLED=false`，不设 `LOCAL_URL`。
4. 本机 `.env` 只允许当前用户读取，例如 POSIX 系统 `chmod 600 .env`。Windows 使用对应文件 ACL。

```bash
docker version
docker compose version
cp .env.example .env
# Edit .env now: replace the token; keep cloud disabled.
chmod 600 .env
make install
make check
make test
make attacks
make verify
make run
```

首次安装/构建需要外网依赖源。`make install` 在 Docker 内执行 `npm ci`；不是宿主机运行 Node。若没有 Make，等价地使用项目 Makefile 中的 Docker 命令，启动可直接运行 `docker compose up --build`。任何检查失败先解决，不要把失败跳过后写成通过。

### 无 Docker 的已批准宿主开发方式

本项目已允许在缺少 Docker 的开发环境使用宿主工具链。需要已有可用 Node.js/npm 和 Rust/Cargo；锁文件决定依赖版本，不使用任意 `latest`。这不替代容器构建与部署验收。

```bash
npm ci --ignore-scripts
cargo build --release --locked --manifest-path rust-core/Cargo.toml
cargo test --locked --manifest-path rust-core/Cargo.toml
npm run typecheck
npm run lint
npm run test:all
npm run build
# Inject GATEWAY_TOKEN and configuration into the environment first.
npm start
```

直接 `npm start` 不自动读取 `.env`。安全地在当前 shell/服务管理器注入配置，或在支持该参数的 Node 版本运行 `node --env-file=.env dist/src/server.js`。默认 Rust 可执行文件须先构建；纯 TypeScript 模式需显式 `PRIVACY_SCANNER=typescript`，记录为不同检测配置并单独测试。完整构建/测试命令以当前 Makefile 和 Rust 核心说明为准。

## B. 无 key 体验

打开 `http://127.0.0.1:3000`，输入网关访问 token。此 token 只用于本机网关，不是供应商 key。

| 输入/操作 | 期望结果 |
|---|---|
| `Summarize alice@example.test`，仅本地、未知 | 检测邮箱；路由留本地 |
| 执行本地处理 | 明确显示合成演示，未调用模型 |
| 同一请求再次执行 | 拒绝已消费请求 |
| 检查后等待超过 120 秒再执行 | 请求过期，重新检查 |
| 机密或未知分类，尝试混合模式 | 留本地，不因用户偏好自动上云 |
| 上传 PDF/图片/压缩包 | 拒绝或由 UI 阻止，不悄悄抽取部分内容 |
| 刷新页面 | 清除页面内凭据和未持久化状态；需要重输 |

这些是操作员验收步骤，不是已替你在目标环境执行的记录。请记录每项实际结果、浏览器和构件版本。不要将合成演示输出当成模型能力。

## C. 本地模型联调

按[接入指南](07-本地隐私网关.md)配置已有 Ollama/vLLM 或其他兼容模型。先确认模型权重与许可，再确认模型确实只在受控环境执行。

```bash
# After editing LOCAL_URL, LOCAL_MODEL and the allowlist:
docker compose up -d --build --force-recreate
docker compose ps
```

刷新页面，状态应从合成演示变为本地模型。用合成提示验证输出，再停止模型服务，重新检查并执行：应收到明确失败，**没有云回退**。恢复服务后需创建新请求。不能只看 `status` 就认定模型健康，该接口展示配置，不会探测上游模型。

## D. 云端试点联调

先完成组织批准、供应商合同/地区检查、出网白名单，再配置云端 HTTPS URL、模型和运行时 key。不要在共享文档记录真实 key。

1. 开启 `CLOUD_ENABLED=true` 并重启，使用全新的合成提示。
2. 选择混合模式和公开分类，检查文本。确认 UI 先呈现完整预览，而非立即发送。
3. 不批准时，网络观察应无云请求。用受控代理或出口日志验证目标，不记录正文。
4. 人工批准，再观察一次云调用及本地回填结果。回填仅对模型原样返回的占位符有效。
5. 测试重复 receipt、过期、秘密样例和上游失败，应拒绝或报错，不自动重试/转移供应商。
6. 将 `CLOUD_ENABLED=false` 并重建服务，确认新的检查不能进入云批准流程。关闭不能撤回已完成或在途发送。

仅在合成数据上联调不能证明真实个人信息或商业秘密识别有效。客户语料检测验证是另一道上线门槛。

## E. 离线准备

无 key 演示的**运行阶段**无需模型或云服务；这不意味着空白机器可离线构建。提前在获准联网的构建环境取得源码、锁文件对应依赖、基础镜像并完成构建/验证，然后转移已构建镜像。

```bash
# In the approved build environment:
docker build -t privacy-gateway:pilot .
docker image inspect privacy-gateway:pilot --format '{{.Id}}'
docker save privacy-gateway:pilot -o privacy-gateway-pilot.tar

# On the offline target, after verifying transfer integrity:
docker load -i privacy-gateway-pilot.tar
docker run --rm --name privacy-gateway \
  --env-file .env -e HOST=0.0.0.0 \
  -p 127.0.0.1:3000:3000 \
  --read-only --tmpfs /tmp --cap-drop ALL \
  --security-opt no-new-privileges:true privacy-gateway:pilot
```

离线目标仍需预装 Docker；如使用本地推理，还要预置推理服务镜像、全部模型文件、tokenizer/chat template 与必要驱动，并检查其不会在线补下载。不要复制 `.env`、真实数据或个人缓存到镜像。Docker 的 `save/load` 用于传输镜像，不能替代来源、完整性与漏洞审查。[Docker save](https://docs.docker.com/reference/cli/docker/image/save/)、[Docker load](https://docs.docker.com/reference/cli/docker/image/load/)

## F. 关闭和回滚

```bash
docker compose down
```

结束前确认没有需要保留的已授权结果。内存请求和批准不能在重启后恢复。若发生事故，先按事件流程关闭云端并阻断出口，再回滚至已审查镜像摘要；不要从未知 `latest` 重建。回滚后重新运行合成 smoke test：检查 → 本地处理 → 重放拒绝 → 机密不外发。旧版文档里的 create/accept/revoke handoff smoke test 不适用于本次网关。

## 常见问题

- **页面打不开**：确认 Docker 正在运行、3000 端口未占用、容器启动成功；只查看不含秘密的错误信息。Compose 默认不向局域网发布。
- **401**：网关 token 不匹配。检查运行时注入值，刷新后重新输入，不把供应商 key 填入页面。
- **403 origin**：代理后的请求 origin 与后端认知不一致。让平台团队审查代理和同源配置，不要直接关闭校验。
- **本地连接失败**：容器的 `127.0.0.1` 是容器自身。按部署网络选择宿主或 sidecar 名称，并同步精确白名单与防火墙。
- **502**：检查模型名、完整 URL、协议、鉴权、响应格式/大小和超时。原始上游错误不向浏览器回显。
- **429**：入口有全进程速率限制，另有待处理请求容量限制。检查负载或滥用，勿盲目扩容。
- **想处理 Word/PDF**：当前不支持。必须另行评估可信转换和元数据处理，不能改后缀上传。
