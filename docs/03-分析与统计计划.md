# 03 分析与统计计划

> 一句话故事：本文用 statsmodels 的 MixedLM（线性混合效应模型）在 run-level 估计臂 × 拓扑 × 规模 × 任务的固定效应与种子随机效应，用 bootstrap 间接效应做中介检验，用 BH-FDR 控制臂 × 成分的多重比较，并在 numbers_manifest.json 里把每一个数字变成可离线校验的 key；失败情形按预注册的写法如实报告，禁止把负面结果包装成 superiority。

## 3.1 分析目标与单元

**单元**。`spec/COORDINATION-COST-SPEC.md` 的伪重复警告仍生效：分析单元是 **一个 run**（一个 cell × 一个 seed），不是单个 handoff 也不是单个 API call。所有聚合在 run-level 完成。

**目标层级**。

- **L1 描述**：每个臂的 cost 分布与 cost_per_success。
- **L2 主分析**：H1–H5 的固定效应与交互项。
- **L3 中介与异质性**：C_search / C_adapt 的中介作用，task × N 的异质性。
- **L4 鲁棒性**：成本货币替换、模型替换（开源子集）、截断 run 的影响。

## 3.2 主分析模型：线性混合效应（MixedLM）

### 3.2.1 形式化

因变量 `cost_per_success_usd`（在三个货币下分别估计一次）。混合模型：

```
cost_per_success_ijkt ~ β0
                        + β1 D_S              (S vs F)
                        + β2 D_C              (C vs F)
                        + β2b D_CSH           (C-shadow vs F; 子研究才有非零)
                        + β3 topology_t       (4 levels, 3 dummy)
                        + β4 log(N)           (中心化 + 对数尺度)
                        + β5 task_k           (3 levels, 2 dummy; T0 在 smoke 中)
                        + β6 (D_S × task)     (H1 的异质性)
                        + β7 (D_CSH × task)   (H2 的异质性,不是 D_C)
                        + β8 (D_CSH × U_task) (H3 的不确定性交叉)
                        + β9 (D_S × log N)    (H5 的规模交叉,预期为负)
                        + u_cell              (cell-level random intercept)
                        + ε_ijkt              (residual)
```

**为什么 H2 用 `D_CSH` 而不是 `D_C`**：强制生效时越界动作根本不会发生,`C_adapt` 在 `C` 臂上按构造归零,所以 `D_C` 那一格不是行为观测而是架构属性,拿它做中介分析就是循环论证。`D_CSH` 用同一套消息设计但网关只验签记录、随后放行,越界动作真的会发生,返工因此可观测。**主网格的 3 臂行里 `D_CSH` 恒为 0**,它只在机制子研究的行上取 1,见 3.9。

**`D_C` 在模型里仍然保留**,但只用来报 `C_adapt` 的**退化格对照**,不参与 H2 的检验,也不得与 `S` 直接相减。

下标 `i = run`, `j = arm`, `k = task`, `t = topology`。

- **随机效应**：`u_cell ~ N(0, σ²_cell)`，对 cell = arm × task × topology × N×100 编码 unique id，吸收 cell 级别的异质性（同一 cell 下多个 seed 的相关性）。
- **聚类**：标准误按 cell 聚类（`MixedLM(..., groups=cell_id)`），吸收同一 cell 内 run 的非独立性。
- **方差结构**：默认 `Identity`（即 cell-level 同方差）；备选 `heteroskedastic`（按 arm 分组方差），模型选择用 BIC。

### 3.2.2 公式化（statsmodels 调用）

```python
import statsmodels.formula.api as smf

model = smf.mixedlm(
    "cost_per_success_usd ~ D_S + D_C + D_CSH + C(topology) + np.log(N) "
    "+ C(task) + D_S:C(task) + D_CSH:C(task) "
    "+ D_CSH:U_task + D_S:np.log(N)",
    data=df_run,
    groups=df_run["cell_id"],
)
result = model.fit(method="lbfgs", reml=True)
print(result.summary())
```

`arm` 是 `pd.Categorical` 且 `categories=["F", "S", "C", "C-shadow"]`,参考水平 `F`。这样 `β1` 是 S vs F,`β2` 是 C vs F,`β2b` 是 C-shadow vs F;跑 `arm` 上的成对对比可得 **C-shadow vs S**,这就是 H2 的检验量。`arm` 的类别顺序固定为这四个,新增臂不许插在中间,否则所有对比编码都会平移。

### 3.2.3 收敛与诊断

- 收敛用 `lbfgs` 默认先跑；若 `converged=False`，切回 `powell`；
- 残差正态性用 `jarque_bera` 检验；
- 同方差用 `Breusch-Pagan`；
- 离群点用 `studentized_resid > 3` 标，不删除，落盘到 `outliers.csv`，在 Threats to Validity 报告；
- 随机效应方差为 0 时退化为 OLS 并报告降级原因。

### 3.2.4 为什么用 MixedLM 而不是 ANOVA / t 检验

- **跨 cell 异方差**：ANOVA 假定各 cell 同方差，混合模型显式地允许 cell-level variance；
- **多水平**：run 嵌套在 cell，ANOVA 单层 t 检验会过松；
- **regulatory 期望**：CIST / ICIS 审稿人偏好 reporting 标准（marginal R², conditional R²），由 MixedLM 给出。

### 3.2.5 多元因变量：在每个成分上分别跑

`cost_per_success` 在 C_search / C_spec / C_coord / C_adapt 四个成分上分别 fit 一次。`Q`（质量）单独 fit（用 `success_binary` + logit，`success_rate` 用 beta regression）。`cost_per_success_total` 也 fit 一次。

## 3.3 中介分析：C_search / C_adapt 的间接效应

### 3.3.1 模型

中介变量为 `C_search` 与 `C_adapt`（对其他两个成分做敏感性分析）。自变量为设计对比（D_S 与 D_C 两个 dummy），结果变量为 `cost_per_success_total`。

**检验法**：Bootstrap 间接效应（B-K 中介路径 a × b 在标准化路径下报告；5000 次 bootstrap，BCa CI）。

```python
def indirect_effect_bootstrap(df, X, M, Y, n_boot=5000, seed=42):
    rng = np.random.default_rng(seed)
    boots = np.zeros(n_boot)
    n = len(df)
    for b in range(n_boot):
        idx = rng.integers(0, n, n)
        d = df.iloc[idx]
        # path a: X -> M
        a_model = smf.ols(f"{M} ~ {X}", data=d).fit()
        a = a_model.params[X]
        # path b: X, M -> Y controlling X
        b_model = smf.ols(f"{Y} ~ {X} + {M}", data=d).fit()
        b = b_model.params[M]
        boots[b] = a * b
    return np.percentile(boots, [2.5, 97.5])
```

**预期路径**：

- H1：`D_S → C_search ↓ → cost_per_success_total ↓`
- H2：`D_C → C_adapt ↓ → cost_per_success_total ↓`

### 3.3.2 直接效应与完全中介

当 controlled direct effect (c′) 与 total effect (c) 同时显著但间接效应 (a*b) 不显著，按 `preacher-hayes` 的判定为 **no mediation**；当 a*b 显著，按 `Kenny 2021` 的判定报告 partial 或 full。

### 3.3.3 与 02 实验设计中的机制字段联动

中介分析的解释只有在 02 中的 `c_blocked_by_enforcement` / `verify_failures` 等机制字段与臂预期一致时才能成立。如果 C 与 S 的 `verify_failures` 没差异（即 verify 实现在 S 上也是机器执行的），H2 失去机制，必须改写论文讨论。这是中介分析的反向鲁棒性检查。

## 3.4 多重比较控制

### 3.4.1 BH-FDR

采用 Benjamini-Hochberg 1995。控制 `q = 0.05`。每个假设家族独立控制：

| 家族 | 内容 | 检验数 K | 控制 |
|---|---|---|---|
| F1 | 主分析 arm 对比（S vs F, C vs F, C vs S）在 4 个成本成分上的 12 个 t 检验 | 12 | BH-FDR（q=0.05） |
| F2 | H3 的 task × arm 交叉在每个 task 内的臂对比 | 3 task × 12 = 36 | BH-FDR（q=0.05） + **power 门禁** |
| F3 | H5 的规模交叉在每个 N 内的臂对比 | 3 N × 12 = 36 | BH-FDR（q=0.05） + **power 门禁** |
| F4 | 中介分析：4 间接效应 × 3 货币 × 2 成分 = 24 | 24 | BH-FDR（q=0.05） |

为什么分家族而非全 pool：multi-arm × multi-component 的全局控制会过保守，分家族保留 H3 / H5 的探索性。

### 3.4.2 进入主实验前的 power 门禁（阻塞项）

F2 与 F3 均为 K=36 经 BH 校正后衰减显著的家族。在跑主网格 cell 之前，**两者均必须通过 power simulation 门禁**：

- 仿真目标：在 R=20、design effect=2.9（ICC=0.10, m=20）下，**power ≥ 0.80** 检测 `d=0.3` 的中等效应。
- 不达标的处理：扩 R（提高到 30 / 40 / 60），或**修订假设家族**（合并 task、合并 N 集合）。
- 修订均**走 OSF revision 通道**（与 2.11.4 同级），不留 silent fallback。
- 仿真代码与原始结果归档在 `analysis/power/family_F2.py` 与 `analysis/power/family_F3.py`，并落入 `numbers_manifest.json`：`power.family_F2.d03.R20.power`、`power.family_F3.d03.R20.power`。
- 此门禁对应 2.11.1 第 13 项（"功效复核已完成"），是 P3 主网格启动的前置条件；未完成不得开跑。

为什么这是阻塞项：H3 在"高 U 任务上 C 比 S 更省"这个正面结果若 power 不达标，最容易在审稿人处被识别为 false positive；扩 R 不昂贵，延误投稿才是最贵的成本。

### 3.4.3 报告规范

每个 p 值报原始 + 校正后 `q`；报 BH 拒绝门槛（拒绝线）。把 q > 0.05 的视为探索性，不进入正文结论，进入附录 F。

### 3.4.4 为什么不用 Bonferroni

Bonferroni 在本研究过度保守（会增加假阴性）。审稿人通常接受 BH-FDR 作为 multi-comparison 控制；接受 Bonferroni 是退路。两种都给。

## 3.5 效应量（effect size）

### 3.5.1 Cohen's d

复用 ASAS 的 `cohens_d()`：

```python
from experiments.analysis.statistics import cohens_d
d = cohens_d(group1, group2)
```

Cohen 1988 解释阈值（小 / 中 / 大）：0.2 / 0.5 / 0.8；本研究因 cell 量级 R=20 + 种内变异采用 adjusted Cohen's d（Hedges' g），用 `n1, n2` 加权：

```
g = d * (1 - 3 / (4 * (n1 + n2) - 9))
```

### 3.5.2 边际 R² 与条件 R²

MixedLM 报告：

- `marginal R²` = fixed effects 解释方差比例
- `conditional R²` = fixed + random 解释方差比例

目标：`conditional R² ≥ 0.5`。否则意味 cell-level 异质性远大于模型能解释，要重新设计 cell 编码。

### 3.5.3 弹性估计（H5）

H5 的超线性用对数弹性：

```
log(cost_per_success_usd) ~ log(N) + D + D:log(N)
```

`β(D:log(N)) > 1` 表示超线性（在 N 上加速）。

```python
def bootstrap_ci(data: List[float], statistic=np.mean,

### 3.6.2 调用范式

pt, lo, hi = bootstrap_ci(
    df_run["cost_per_success_usd"][df_run.arm == "S"].values,
    statistic=np.mean,
    n_resamples=10000,
    seed=osf_master_seed_int,  # 与 bench prereg 中的 master_seed 一致

```

### 3.6.3 cluster-bootstrap 函数（需新建）

ASAS 的 `bootstrap_ci` 不支持 cluster，需在本项目 `analysis/bootstrap.py` 新增：

```python
def cluster_bootstrap_ci(data, cluster_ids, statistic=np.mean,
                          n_resamples=10000, seed=42):
    rng = np.random.default_rng(seed)
    clusters = np.unique(cluster_ids)
    points = []
    arr = np.asarray(data)
    for _ in range(n_resamples):
        sampled = rng.choice(clusters, size=len(clusters), replace=True)
        idx = np.concatenate([np.where(cluster_ids == c)[0] for c in sampled])
        points.append(statistic(arr[idx]))
    arr_stat = statistic(arr)
    return arr_stat, np.percentile(points, 2.5), np.percentile(points, 97.5)
```

## 3.7 假设的检验、统计量与事前功效要求

### 3.7.1 H1：结构降低 C_search / C_spec

- **检验**：Wald test on `β1`（D_S），分别在 C_search 与 C_spec 子模型上。
- **统计量**：MixedLM z 统计量。
- **拒绝规则**：`q_BH < 0.05`。
- **预期效应**：Cohen's d > 0.3（S vs F）。
- **功效**：要求 power 0.80 在 R=20 / 96 / 96 cell 下检测 d=0.3；模拟给出 R_min。
- **敏感性**：non-cluster bootstrap CI 不能含 0。

### 3.7.2 H2：承诺降低 C_adapt

- **检验**：Wald test on **`C-shadow` vs `S`** 的对比,在 `C_adapt` 子模型上。**不是 `C` vs `S`。**
- **统计量**：MixedLM z 统计量。
- **拒绝规则**：`q_BH < 0.05`。
- **为什么不能用 `C` vs `S`**：强制生效时越界调用不会发生,没有工作被做,因此没有东西可以返工,`C` 臂的 `rework_rounds` 与 `out_of_scope_actions` 按构造归零。那一格测的是网关,不是 agent。拿它做 H2 就是循环论证,详见 `../spec/COORDINATION-COST-SPEC.md`。
- **机制证据**：`c_blocked_by_enforcement(C) > 0`（否则签名为空档）;`c_blocked_by_enforcement(C-shadow) > 0` 且 `C-shadow` 的 `rework_rounds` 确实非零,证明探针臂真的放行了越界动作而不是被意外拦截。**第二个条件是 `C-shadow` 自身的 sanity check,没有它整条链失效。**
- **预期效应**：Cohen's d > 0.4(C-shadow vs S)。
- **主网格里的 `C` 臂**：`C_adapt` 标为退化格,如实报告,不进 H2 检验,不与 `S` 相减,也不进 CCI 的主榜。见 3.9。

### 3.7.3 H3：承诺收益在不确定性高的任务上最大

- **检验**：混合模型交互 `D_CSH × U_task` 的 F 检验(单自由度 contrast)。
- **预期方向**：`β > 0`,在 Δcost_per_success = cost(S) − cost(C-shadow) 上;即高 U 上 C-shadow 比 S 更省。
- **拒绝规则**：交互项 `q_BH < 0.05`。
- **post-hoc**：每个 task 内对比 C-shadow vs S,分别报效应量;负效应(低 U 时更贵)作为探索性子结果,即过度契约。
- **U 的编码**:`T0` 低、`T1` 中、`T2` 中、`T3` 高,与 `docs/02` 第 2.6 节一致。

### 3.7.4 H4：成本转移而非消失

- **检验**：分别 fit `sender_tokens ~ D` 与 `receiver_tokens ~ D` 两个 OLS,对比方向。
- **预期**：`β_sender(D_C) > 0`,`β_receiver(D_C) < 0`,总效应接近 0 或为负。
- **拒绝规则**：方向检验(非参数 sign test)+ 90% bootstrap CI on `(β_sender + β_receiver)` 不含 0 或在 0 边缘。
- **敏感性**：移除 C 中 token 字节(仅留 JSON)的 ablation 作为对照。

### 3.7.5 H5：规模超线性

- **检验**：log-log 回归 `log(cost_per_success) ~ log(N) + D + D:log(N)`,看 `β(D:log(N))`。
- **预期方向**：**S vs F 的 `β(D:log N) < 0`**。因为因变量是成本,交互项为负意味着结构化臂的成本随 N 增长得**更慢**,也就是结构化的节省随规模**扩大**。这与 H5「收益超线性增长」一致。
- **符号陷阱**：写成 `β > 0` 会预测结构化成本增长更快,正好与 H5 相反,会把头条结论翻转。**判据只有一条：`β(D:log N) < 0`。**
- **拒绝规则**：`q_BH < 0.05`,且 cluster-bootstrap CI of `β(D:log N)` **不含 0**。注意不是「CI 在 1 之上」:那是成本对 N 的水平弹性检验,不是臂间对比的交互检验,两者不能混。
- **补充参数化(读者更好懂)**：直接对 `benefit(N) = cost_F(N) − cost_S(N)` 回归 `log(benefit) ~ log(N)`,斜率 `> 1` 即收益超线性。两个参数化都报,结论必须一致;不一致本身就是一节 Limitations。
- **补充**：分别 fit 在每个 topology 上(chain / tree / hub-and-spoke / mesh),报告每臂每拓扑的斜率。

### 3.7.6 事前功效（pre-study power analysis）

```python
from statsmodels.stats.power import FTestAnovaPower
# per-cell n needed to detect d=0.3 with power=0.80, alpha=0.05
n_min = FTestAnovaPower().solve_power(effect_size=0.3, alpha=0.05, power=0.80)
# 应用 cluster inflation factor: design_effect = 1 + (m-1)*icc
# 假设 icc=0.10, 平均 cluster size m=20 → DE=2.9 → effective n ≈ 60
# 即 cell-level 需 R=60。
```

主网格默认 R=20；按 ICC 校准到 R=60。预计 N=96 mesh 减少 R=10，其余同。

## 3.8 异质性分析

### 3.8.1 任务不确定性作为调节变量

每个 task 有 `U_task ∈ {low, mid, high}` 标签：

- T0 = low
- T1 = mid
- T2 = mid
- T3 = high

定义后写入 metadata。在 H3 的模型中作为连续变量（1/2/3 或 z-scored）。

### 3.8.2 规模 N 作为调节变量

`log(N)` 入模型，标准化。H5 的超线性测试在此完成。

### 3.8.3 拓扑作为辅助调节变量

虽然 H1–H5 不直接预测 topology 主效应，但作为 exploratory：

- topology × arm 交互的 β 是否为 0；
- chain vs tree vs hub-and-spoke vs mesh 上臂间差距的 budget 是 H5 之外的 reflection。

不进预注册结果，进附录 D（Exploratory subgroup analyses）。

### 3.8.4 模型子集（仅 chain 跑一次）以纯净 H5

chain 上 N↑ 时路径数线性增长，最能剥离拓扑混杂。`log(cost_per_success) ~ log(N) + D + D:log(N)` 在 chain-only 子集 fit。

## 3.9 `C-shadow` 机制子研究

主网格是 3 臂，这是不变的部分。`C-shadow` 是**另立门户的机制子研究**，不是主网格的第四臂。

### 3.9.1 为什么单列

`C` 臂的 `C_adapt` 是**退化格**：强制生效时越界调用不会发生，因此没有工作被做，没有东西可以返工。把它和 `S` 相减，得到的不是承诺的效果，是网关的效果。这条理由与 `../spec/COORDINATION-COST-SPEC.md` 的「`C_adapt` 在 `C` 臂上退化」一节相同。

### 3.9.2 设计

| | 无显式声明 | 有显式声明 |
|---|---|---|
| 无强制 | `S` | `C-shadow` |
| 强制 | **结构性空缺**（没有声明就没有可强制的对象） | `C` |

`C-shadow` 用 `C` 的消息设计与 token，网关只验签、记录 `c_would_block`、随后放行。实现上就是网关的一个布尔开关，`encode` / `decode` / `renderToProse` 都不动。

### 3.9.3 格子与预算

| 维度 | 子研究取值 | 主网格 |
|---|---|---|
| 臂 | `S`、`C-shadow`、`C` | `F`、`S`、`C` |
| 任务 | `T2` only | `T1`、`T2`、`T3` |
| 拓扑 | chain、hub-and-spoke | 全部四种 |
| 规模 | 8、32 | 8、32、96 |
| 检验的假设 | 只有 H2 的机制 | H1 至 H5 |

**不进主网格的理由**：算力。主网格加一臂意味着每个 cell 多一个 run，但真正贵的是 `N=96` 与 `N=128` 那几格，子研究一概不碰。子研究只在 `T2`、`chain` 与 `hub-and-spoke`、`N∈{8,32}` 上跑，约 80 个 run，对主网格 825 个 run 的增量约 10%，按调用量算更低。frontier API 的预算是明确风险，这 10% 花在唯一需要它的那个对比上才值。

### 3.9.4 预注册与预算行

子研究必须**在 OSF 上单独冻结**，并有**独立的预算行**。`docs/02` 第 2.11 与 2.13 节里主网格冻结的字段清单不覆盖 `C-shadow`，所以子研究要另写一份 `substudy-cshadow.md` 进 OSF，并在 `--max-spend` 里单独开一条线。**没有独立预注册与预算行的子研究，等于没做。**

### 3.9.5 两条 sanity check

子研究成立的前提是 `C-shadow` 真的放行了越界动作。跑之前先验：

1. `c_blocked_by_enforcement(C-shadow) > 0`，即确实有越界动作本该被拦。
2. `C-shadow` 的 `rework_rounds` 显著非零，即越界动作真的造成了返工。

**两条任一不成立，子研究无效**，因为那说明探针臂没有起到探针的作用。检查写在 `docs/02` 的预注册里，不允许事后补。

### 3.9.6 报告规则

- 主网格里 `C` 臂的 `C_adapt` 标为退化格，如实报告，不进 H2 检验，不与 `S` 相减，不进 CCI 主榜。
- 图表中 `C_adapt` 的 `C` 那一格必须视觉上区分（斜线填充 + 标注），不允许画成普通柱。
- 论文里 H2 的表述只能是「承诺作为**信号**降低事后适应」加上「强制提供的是**拦截计数**，不是适应成本效应」。任何把 `C` 的低适应成本当成发现的写法，都是把架构属性写成了行为发现。

## 3.10 数字可校验性：numbers_manifest.json 设计

### 3.10.1 设计目的

`results/numbers_manifest.json` 把论文里每一个数字变成一个 key：value + 数据来源 + 生成函数 + git SHA + prereg_id + data_seen + fmt。任何数字都能用 `verify_numbers.py` 离线重算。

参考 OC-P1 的字段 schema（已读其 `results/numbers_manifest.json` 字段结构）：

```json
[
  {
    "key": "bias.case.ext.ds.cr0.eligible",
    "value": 0,
    "source_file": "results/raw/sim_ext/ext_eval_set.csv;results/raw/r2/RM-B.jsonl",
    "function": "experiment.analysis.bias.gap_share",
    "git_sha": "00c97f02d751+dirty",
    "prereg_id": "S10",
    "data_seen": "unseen",
    "fmt": "int"
  }
]
```

### 3.10.2 本研究 manifest schema

```json
{
  "schema_version": "0.1.0",
  "key": "h1.cost_usd.arm.S.path.cs.median",
  "value": 12.4,
  "source_file": [
    "results/raw/main/*.jsonl",
    "results/processed/run.parquet"
  ],
  "function": "analysis.stats.point_estimate(df_run, arm='S', cost_col='cost_usd', component='C_search', stat='median')",
  "git_sha": "<auto>",
  "prereg_id": "osf/handoffpack-prereg-2026-12",
  "data_seen": "seen_at_prereg",
  "fmt": "f2",
  "ci": {"lo": 11.0, "hi": 13.8, "method": "cluster_bootstrap", "n_boot": 10000, "alpha": 0.05},
  "n_obs": 120,
  "cell_id": "S-T2-chain-32"
}
```

字段说明：

- `key`：`{hypothesis}.{outcome}.{design}.{arm}.{cost|effect}.{aggregation}`，惯例化命名保证可正则解析。
- `value`：数值，与论文中位数严格一致。
- `source_file`：`;`-分隔的路径，支持多源。
- `function`：生成该 key 的 Python 表达式；以 `analysis.*` 模块名开。
- `git_sha`：自动从 `git rev-parse HEAD` 取。
- `prereg_id`：OSF 注册号。
- `data_seen`：`unseen` / `seen_at_prereg` / `post_hoc`；`post_hoc` 标记未在预注册中预期的 key（审稿人的探索性发现必须带此 tag，否则论文正文不报）。
- `fmt`：显示格式 `f1` / `f2` / `f3` / `int` / `pct` / `pct1`。
- `ci`：可选，含方法、重采样数、显著性水平。
- `n_obs`：聚合前的样本数。
- `cell_id`：哪个 cell 出的；`all` 表示全集。

### 3.10.3 关键 key 清单与论文中数字对应

下表把论文里会出现的关键数字对应到 manifest key。P3 进入分析前要全部就绪。

| 论文中数字 | manifest key 示例 |
|---|---|
| "S 相对 F 在 C_search 上降 24%" | `h1.cs.usd.S_vs_F.rel.median`, `h1.cs.usd.S_vs_F.q_bh` |
| "C 相对 S 在 C_adapt 上降 38%" | `h2.ca.usd.C_vs_S.rel.median`, `h2.ca.usd.C_vs_F.q_bh` |
| "H3 在 T3 上 C 的边际效应为正" | `h3.t3.C_vs_S.d.median`, `h3.t3.C_vs_S.ci_lo_hi` |
| "H5 log-log 斜率 S vs F = 0.45, C vs S = 0.72" | `h5.chain.loglog.S_vs_F.beta`, `h5.chain.loglog.C_vs_S.beta` |
| 公平性：`tokens(C)/tokens(S) = 1.21` | `fair.tokens_ratio.C_over_S.median` |
| 漂移：跨月 β 变化 | `drift.h1.cs.beta.delta_90d` |

### 3.10.4 `verify_numbers.py`

在 `analysis/verify_numbers.py` 实现：

```python
import json, hashlib, sys

manifest = json.load(open("results/numbers_manifest.json"))
source_files = set()
for entry in manifest:
    for f in entry["source_file"]:
        source_files.add(f)

# 1. 配置文件未变
subprocess.run(["sha256sum", "-c", "bench/prereg/CONFIGS.sha256"], check=True)

# 2. source_files 全部存在
for f in source_files:
    assert os.path.exists(f), f"missing {f}"

# 3. 重算每个 entry 的 value
for entry in manifest:
    fn = import_function(entry["function"])
    computed = fn()
    assert abs(computed - entry["value"]) < tolerance_for(entry["fmt"]), \
        f"mismatch {entry['key']}: {computed} != {entry['value']}"

print(f"OK {len(manifest)} keys verified")
```

在 `make verify` 入口运行；任何不一致都阻断 `make figures` 与论文编译。

### 3.10.5 失败模式的可追溯性

若某 key 在重算后不匹配，记录：

- `entry["function"]` 不再可执行（API 模型退役）；
- 此时不删除该 key；改为标 `data_seen = "deprecated"`，并指向替代 key。
- 论文引用 deprecated 的数字时，进 footnote 解释替代 key 与差。

## 3.11 失败情形预案（禁止把负面结果包装成 superiority）

### 3.11.1 不可接受的写作模式

下表逐条列举**禁止出现在论文里**的失败叙事，每条给替代写法。这是 `docs/04-论文计划.md` 的硬规则，本节列具体技术判定。

| 失败叙事（禁止） | 技术判定 | 替代写法 |
|---|---|---|
| "C 在所有任务上以某种口径优于 S" | 实际为：H2 在某个 task 内不显著 | "H2 在低 U 任务上不显著，符合 H3 的预言（边际契约成本吞噬收益）。" |
| "结构化全面降低协同成本" | 实际为：H1 在 C_spec 上显著但在 C_search 上不显著（或反之） | "H1 的两成分上仅 C_spec 一致显著；C_search 在低 U 任务上不显著。" |
| 报 t 检验 p 值不报 BH 校正 | multi-comparison 失控 | 必须报 `q_BH`；除非在 Exploratory 子节，否则去掉。 |
| 用 `mean ± SE` 报成本（偏态） | mean 被高成本 run 拉偏 | 中位数 + IQR，正文中所有 cost 都用此口径；`mean ± SE` 仅在附录 robustness。 |
| 报 optimistic 排除截断 run | 截断是真实成本 | 包含截断 run，单独报截断率；不删除。 |
| 仅报 USD，不报 tokens 与 wall-clock | 货币不完整 | 三个货币并排，给同一表格三栏。 |
| 把 negative result 包装成 “equivalence” | 易被审稿人识破 | 直接说 "non-significant"，并将 power 与 CI 报出。 |

### 3.11.2 何时报“未决”

以下场景按预注册写明报为 “non-significant at planned power”：

- H1 / H2 主效应在某成本成分上 `q_BH ≥ 0.05`；报 mixedlm β 与 95% CI；
- H3 / H5 交互项 `q_BH ≥ 0.05`；报拟合点图 + BCa CI 含 1 或在 0 附近；
- 中介 a*b 的 BCa CI 含 0；报告 indirect effect 不能拒绝零中介。

### 3.11.3 何时报“推翻”

以下场景触发“推翻预注册假设”：

- H1 反向且显著：`q_BH < 0.05` 且 β 方向与预注册相反；同时由于存在 H1 的中介机制字段一致（field observation），不可信，需要重审数据。
- H2 反向：`β(D_C, C_adapt) > 0` 且显著；触发回到 verify 实现核查，看 verify 是否真的在 S 上有效。

### 3.11.4 不可降级处理：误报绕过

不允许“为了 result section 好看”而：

- 去掉截断 run；
- 改 ledger 数值；
- 收紧 acceptance criterion 到让某些 task 自动消失；
- 在分析端重写 task definition。

任何此类动作在 `verify_numbers.py` 中以“source 没被改”方式被挡；如果改 source，则 `CONFIGS.sha256` 自动失效；OSF revision 必须显式 record 触发；论文必须诚实记录。

### 3.11.5 机制字段叙事红线：不可相减

`s_blocked_by_policy` 与 `c_blocked_by_enforcement`（见 2.7.4）在分析中**仅允许分开并列报，禁止相减**。

技术原因：

- F、S 的 `c_blocked_by_enforcement` 是结构性缺失（null），不是 0。把它们从 null 替换为 0 之后做差，会把“签名层没拦住”与“签名层未部署”混为一谈。
- 即便在 C 臂内部，两者度量对象不同：模型自律可以更严（错误地把合法调用拦下），签名执行也可以更严（不接受过期 token）；相减得到的差没有机制意义。

写作要求：

- 正文固定用法为“机制差异（C 独有执行点）”，不写"C 比 S 在该字段上更低"。
- 与之相关的所有 charts / tables 在 caption 里写出：“not subtracted; mechanism delta”。
- 表格原型（与 2.7.4 一致）：

```
arm     |  out_of_scope_actions | s_blocked_by_policy | c_blocked_by_enforcement
F       |  …                    |  …                  |  n/a (no enforcement point)
S       |  …                    |  …                  |  n/a (no enforcement point)
C       |  …                    |  …                  |  …
```

禁止出现的反例：

- “S 与 C 在 `out_of_scope` 字段差 x.x”（混淆差）
- “通过 signature 拦截的次数 = enforced_blocks”（把同名字段拆在不同位置后强行相减）
- 把 `null` 替换成 0 后做 t-test
