# 08 · 本地优先隐私出口网关：生态与集成调研

> 调研日期：2026-11-02。结论：做一个窄而可验证的 egress gate（数据出口闸门），不是再造推理引擎、工作流平台或训练引擎。以下是选型建议，不代表这些组件已经集成或通过测试。

## 1. 先读结论

1. **自己的核心只保留五件事**：本地分流、出站策略判定、最小化与占位替换、受控发送、同一授权会话内本地回填。模型、文件解析器、识别器均可替换。
2. **第一条可交付链路**：本地文本输入 → 本地规则识别 → 本地模型优先 → 明确允许的远端最小请求 → 本地回填。优先兼容 Ollama 与 OpenAI-compatible HTTP 子集，不承诺兼容所有工具调用、文件上传或多模态协议。
3. **第二阶段候选**：Presidio 检测服务、Docling 本地文件解析、OPA 企业策略服务、promptfoo 外部验收套件。它们不是本轮新增依赖，Python/Go 等服务必须经过栈和依赖审批后独立部署，核心仍是 TypeScript/Hono/Zod。
4. **不要直接 fork 全平台**：Open WebUI、Dify、Flowise 适合做接入客户或 UX 参照；LiteLLM 是可选下游路由器，同时也是功能重叠竞品。把网关建在其内部会失去独立可证明的出站边界。
5. **不承诺零泄露**：PII（个人可识别信息）识别不是商业秘密识别，更不是语义匿名化证明。没识别出来、不支持的格式、审批失效、适配器能力不明，默认留在本地或拒绝。

这些是工程判断，不是上游项目对本项目的背书；没有实测精度、延迟、成本或企业客户付费意愿数据。

## 2. 核验口径与许可证边界

- 共整理 **28 个项目或协议对象**，包括开源组件、混合许可/源码可见平台、一个专有运行时与一个 API 兼容约定。不能将 28 项统称为“28 个开源项目”。
- 每行的项目链接为本次已读取的官方仓库或官方文档。许可证“仓库展示”指读取仓库许可标识/README；“正文核验”指读取 LICENSE 正文。两者都只反映访问时主分支，不替代将来固定版本的许可证审查。
- 未核验事项统一包括：最终采用的 tag/commit、依赖树许可证、模型权重/数据集许可证、二进制和容器 SBOM（软件物料清单）、离线遥测行为、真实吞吐与准确率。不得用代码的 MIT/Apache 许可推定模型可商用。
- 公共沟通入口只列项目公开 Issues、Discussions 或官方社区。未收集个人联系方式，未发送任何消息。安全漏洞应遵循各项目 SECURITY 文档，不应公开贴原始私密样本。
- 版本冻结时，记录源码 commit、容器 digest、模型 hash、LICENSE/NOTICE 副本。商用再分发前，针对实际文件清单复核，不把此文当作法律意见。

## 5. 具体该接什么，不接什么

### 5.1 最小组件边界

```text
Client / UI
  -> Local parser and detector
  -> Policy decision
     -> Local model adapter
     -> Deny / review
     -> Approved minimal payload
        -> Egress sender
        -> Optional downstream provider router
        -> Remote provider
  -> Local response validation and scoped restoration
```

- 原文、解析内容和映射只在本地受控边界；加密存储不能抵御已攻陷的本机管理员，需要另列威胁边界。
- 远端模型只负责获准的任务，不负责“理解原始秘密后决定如何匿名”。检测/路由 embedding 也不能先外发原文。
- 审批展示必须是**将实际发送的完整内容与目标**，包括 system、history、工具 schema/arguments、文件提取片段和 metadata。审批 token 绑定 payload hash、策略版本、身份、目的地、过期时间，编辑后重新审查。
- 回填只接受该请求签发的占位符，不为远端任意占位符查询全局映射；先验证会话、授权、过期及输出上下文。回填后的内容若进入下一轮远端请求，必须再次执行出口策略。
- 自动 fallback、重试、重定向、日志、缓存、追踪、插件、OCR、embedding、网页抓取均是独立出口。只有聊天代理时，要在界面写清“只覆盖经过本网关的请求”。

### 5.2 通用 adapter 的合约

候选接口不绑定 SDK：输入为经 Zod 校验的规范化请求；配置有 provider ID、固定 endpoint、local/remote 分类、可用模型、能力表、超时与大小上限；输出为规范化文本/usage/错误。

不能靠请求方传来的 `local: true` 信任目的地。网络目的地由管理员配置并限制；对 DNS、重定向、代理和云模型路径单独验证。未知字段不透传。首期未实现的流式、工具、图片与文件能力应显式报不支持，而不是宽松转发。

**最低适配器合约测试**：非支持能力拒绝；错误不带原文；取消不触发云 fallback；供应商改写占位符时不误回填；跨会话占位符拒绝；同一次批准不能发送修改后的 body；远端失败后只允许策略相同或更严格的路由。

### 5.3 推荐顺序与退出门槛

| 阶段 | 只做这些 | 可判断通过/失败的退出门槛 |
|---|---|---|
| P0 | TS 网关 + mock、本地文本、规则基线、明确策略 | 合成秘密从实际捕获的出站 body 消失；拒绝路径没有网络调用；跨会话不可回填 |
| P1 | Ollama 文本适配、单一获准远端适配 | 本地失败不外发；真实 endpoint 能力矩阵跑通；没有原文/映射进入日志 |
| P2 | 经批准的 Presidio / Docling sidecar | 中英混合、表格、OCR 漏检和不支持格式分别报告；解析失败拒绝；网络隔离测试通过 |
| P3 | 一个真实应用入口，例如 Open WebUI；可选 OPA | 记录所有出站路径及未覆盖部分；审批后改动请求不能发出；策略服务失效拒绝 |
| P4 | 独立回归与企业部署能力 | 留存版本化测试证据、回归集和漏洞处理流程；不以一套红队分数代替安全保证 |

本表是选型路线，不是已通过状态；任何新增依赖或 sidecar 仍需仓库授权。

## 6. UX 与企业变现建议

这是产品假设，应通过试用验证，不是调研已证明的需求或收入。

**用户眼前只需要三种状态**：留在本机、等待检查/批准、已按批准版本发送。不要用单个绿色盾牌暗示绝对安全。每次远端请求可展开看到目的地、字段变化、删减原因和不可还原风险。检测失败、解析不全与离线模型未安装，均给出可执行的本地替代方案。

**差异化不是聊天 UI，也不是“模型多”**：可审计的发送证据、易懂的逐字段预览、可靠本地回填、客户端覆盖清单和默认不外发的失败行为，才是窄闸门价值。已有 UI 做得好的部分通过配置接入，不复制整个产品。

**开源核心候选**：本地网关、策略接口、文本检测基线、adapter 合约、可重放合成验收集、无遥测默认配置。

**企业付费候选**：组织策略分发、SSO/RBAC、审批分权、客户自管密钥、私有部署、经过验证的连接器、审计留存与导出、部署支持/SLA。收费对象是可维护的治理和部署服务，不是“保证永不泄露”，也不靠收集客户原文训练模型。

优先验证一个窄场景，例如企业内部文档摘要的获准远端请求。按每百次请求的人工审批时间、误拦率、用户纠正率、任务质量损失、额外延迟与部署耗时判断价值。价格和 ROI 在真实试点前保持未验证。

## 7. 评测口径与未决项

### 7.1 不借用上游营销数字当自身效果

建立公开合成集，覆盖中文/英文/混排、邮箱/手机号/密钥、客户代号、间接身份线索、表格与隐藏 metadata。分别统计实体级漏检/误报、实际出站敏感串、语义可识别性人工复核、恢复正确率、跨请求隔离、质量损失、延迟与成本。

普通 NER F1 不能代表出口安全。识别器可以失误，而禁止数据类别和未授权目标仍须被确定性阻断。对抗测试只用授权目标和虚构材料，报告样本量、限制和失败案例，不把“本轮零命中”写成“零泄露”。
