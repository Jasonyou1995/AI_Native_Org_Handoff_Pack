# 09 · 生产验收与运维

## 当前结论

本项目是本地优先隐私网关试点。代码级安全措施和合成测试不是独立安全评估，也不是客户真实数据检测有效性的证据。不能据此宣称“生产安全”“零泄漏”“符合所有地区要求”或确定的加速倍数。

上线批准人必须逐项记录证据、负责人、日期和未解决风险。以下任意一项没有签字，只能继续在受控合成数据环境试用。

| 门槛 | 验收证据 | 建议负责人 |
|---|---|---|
| 供应链与版本 | 已审查来源、锁文件、镜像摘要、漏洞结果；部署与测试为同一构件 | 平台工程 |
| 授权范围 | 确认用途属于免费内部使用，或软件对外商业化已取得单独许可；历史 Apache 区域与第三方许可分别保留 | 法务/采购 |
| 独立安全评估 | 覆盖认证、代理绕过、SSRF、XSS、输入边界、批准重放、资源耗尽 | 安全团队 |
| 检测验证 | 客户自行构造或授权使用的代表性语料；按语言/数据种类报告漏报、误报和人工复核结果 | 数据所有者 |
| 真实端点验证 | 本地和云协议兼容、超时、响应大小、占位符保留、费用/容量限制 | 模型平台 |
| 托管出网 | 默认拒绝、显式域名/地址/端口白名单、DNS 与代理治理；含本地模型容器 | 网络安全 |
| 保留与删除 | 浏览器、代理、模型、主机日志、swap、core dump、供应商保留期限与删除流程 | 数据治理 |
| 身份与权限 | SSO/MFA、组织用户授权、网关后端隔离、凭据轮换、离职撤权 | 身份团队 |
| 法律与地区 | 项目和模型许可、供应商地区可用性、数据驻留/跨境、合同与批准 | 法务/采购 |
| 运营 | 监控、告警、响应负责人、回滚演练、备份边界、容量规划 | 运维 |

## 建议网络拓扑

```text
User browser -> TLS + SSO reverse proxy -> isolated gateway
                                             |-> trusted local model
                                             `-> egress control -> approved HTTPS provider
```

网关不是防火墙。`LOCAL_URL` 默认限制 loopback，`LOCAL_ALLOWED_HOSTS` 可由管理员额外放行精确主机名；这种检查只限制目标配置，不能证明该主机上的模型或代理不会转发；例如本地模型服务也可能有云模式。必须禁用这种转发，并在网络侧验证。云端 HTTPS 不是数据驻留保证。不要把管理员可写的 URL 配置暴露给普通用户。

共享工作站或远程使用必须具备访问控制。网关 Bearer token 是共享凭据，不是每人身份、细粒度权限或 SSO。反向代理应终止 TLS、执行 SSO/MFA、限制请求大小和速率、校验访问权限；后端端口只允许代理访问，不能有绕过代理的公开入口。代理可在认证后代注入后端 token，但须移除客户端伪造头，并保护此 token。跨用户请求隔离与逐人批准归属须另行设计和验证，当前实现不应作为多租户服务。

## 凭据和留存

- 用部署平台在运行时注入 `GATEWAY_TOKEN`、`LOCAL_API_KEY`、`CLOUD_API_KEY`。`.env` 只用于受控本机试用，限制权限，不提交仓库、截图、工单或命令历史。环境变量仍可能被有宿主机权限的人读取。
- UI 的网关凭据只保存在页面运行内存，不应存入 `localStorage`；刷新后需重输。不把云端 key 交给浏览器。
- 应用不主动把请求正文或映射写磁盘；内存状态 120 秒后失效，惰性清理不等于在到期瞬间物理擦除。重启清空所有未完成请求。外层日志、模型日志、swap、崩溃转储与备份不在应用承诺范围。
- 只采集必要事件计数、路由、耗时和错误类别；不采集提示、附件、输出、批准凭据或 Authorization。指标标签不可含用户文本。调试抓包只能用合成数据。
- Docker 官方建议对敏感配置考虑 Secrets；本应用目前直接读取环境变量，不能把 secret 文件路径填成 key 并假定自动读取。若采用 Secret Manager，需经审查的启动注入流程。[Docker 环境变量最佳实践](https://docs.docker.com/compose/how-tos/environment-variables/best-practices/)

## 失效处理

| 现象 | 操作 | 禁止做法 |
|---|---|---|
| `provider_unavailable` | 排查地址、模型、认证、15 秒时限及上游状态；重新检查请求后重试 | 自动切云、把原文写日志 |
| 请求/批准过期 | 重新检查文本并重新批准 | 延长旧批准、复用 receipt |
| 容量耗尽 | 等待过期、限制入口速率、调查滥用 | 无界扩大内存缓存 |
| 误检/漏检 | 停止该类数据外发，更新组织词表与测试并复核 | 以 `public` 分类绕过审查 |
| 怀疑泄漏 | 立即关云、阻断出网、按保留政策保全必要元数据并启动事件响应 | 宣称关云能撤回已经发出的请求 |

批准 receipt 是敏感能力凭据。它只绑定当前文本、策略和提供方，单次使用，失败后也不能直接重放；不能代替组织审批。模型回答不可信，输出展示不应执行 HTML、代码或工具操作。

## 测试结果怎么写

分别列出：运行命令、构件版本/摘要、环境、通过/失败/未运行、输出摘要。禁止把 mock provider 测试写成供应商联调；禁止把本机路由小样本写成性能基准；禁止把历史研究规格写成已实现。客户实际部署的延迟、吞吐、费用和检测有效性必须在授权环境中单独测量。
