# Offline installation and release · 离线安装与发布

**Prepare once on an approved connected machine; run the transferred, verified image without Internet access.** A blank machine cannot build this project offline without previously supplied dependencies. The gateway does not bundle Docker, model weights, an inference server or GPU drivers. Commands below are an operator runbook, not evidence that your hardware has passed them.

**在获准联网的机器准备一次，再将经过验证的镜像转移到无互联网环境运行。** 空白机器若没有预置依赖，无法离线构建。网关不附带 Docker、模型权重、推理服务或 GPU 驱动。以下是操作手册，不是目标硬件已通过检查的证据。

## Prebuilt pilot bundle · 预构建试点包

The release workflow prepares `v0.1.0-alpha.1` for **linux/amd64 only**. Check the [release listing](https://github.com/Jasonyou1995/AI_Native_Org_Handoff_Pack/releases) for an actually published prerelease and its validation notes. Until the assets exist and their checks pass, use the manual preparation below; do not assume a promised release is available. This image does not include a model.

发布工作流准备的 `v0.1.0-alpha.1` **仅针对 linux/amd64**。先查看[发布列表](https://github.com/Jasonyou1995/AI_Native_Org_Handoff_Pack/releases)，确认预发布资产真实存在及其验证记录。资产存在且检查通过前，请用下方手动准备方式，不把计划当成已发布。镜像不含模型。

Download all five assets to one directory on an approved connected machine, then transfer them together: `privacy-handoff-gateway-linux-amd64.tar.gz`, `privacy-handoff-gateway-source.tar.gz`, `manifest.json`, `RELEASE-NOTES.md`, `SHA256SUMS`. Keep a trusted copy of the expected checksums. On the offline target with Docker already installed:

在获准联网机器将上述五项资产下载到同一目录，一并转移，另保留可信摘要。在已预装 Docker 的离线目标执行：

```bash
sha256sum --check SHA256SUMS
gzip -dc privacy-handoff-gateway-linux-amd64.tar.gz | docker image load
IMAGE=privacy-handoff-gateway:v0.1.0-alpha.1-linux-amd64
docker image inspect "$IMAGE" --format '{{.Id}}'
cat manifest.json
# Compare the displayed image ID exactly with manifest.json imageId.
# Confirm sourceCommit and platform against the release notes.
mkdir source
tar -xzf privacy-handoff-gateway-source.tar.gz -C source
```

Stop if any checksum, image ID or platform differs. Open the extracted source root containing `.env.example`, then follow section 3's configuration and `docker run` command using the `IMAGE` value above. Do not use section 3's manual-bundle filenames for these release assets. Docker Desktop on Apple Silicon is not native linux/amd64 hardware; emulation has not been validated by this release.

摘要、镜像 ID 或平台不符即停止。进入解压后包含 `.env.example` 的源码根目录，按第 3 节配置与 `docker run` 命令启动，沿用上面的 `IMAGE`。不要把第 3 节手动包的文件名套用于发布资产。Apple Silicon 上 Docker Desktop 并非原生 linux/amd64 硬件，该版本未验证模拟运行。

## 1. Choose an explicit mode · 选择明确模式

| Mode · 模式 | Required locally · 本地所需 | Network requirement · 网络要求 |
|---|---|---|
| Synthetic demo · 合成演示 | Gateway image + Docker + browser · 网关镜像、Docker、浏览器 | Browser reaches localhost; no model or cloud · 浏览器访问本机，不调用模型或云 |
| Offline inference · 离线推理 | Above + model service, weights, tokenizer/template, drivers if needed · 再加推理服务、权重、tokenizer/template及所需驱动 | Gateway reaches only approved local/LAN model · 网关仅能访问批准的本机/内网模型 |
| Hybrid · 混合模式 | Cloud provider configuration and approval · 云端配置与批准 | Requires external network; **not offline** · 需要外网，**不是离线** |

An isolated LAN can still connect employees to an internal model without Internet access. A physically disconnected single laptop is a different deployment. Select and test your exact topology. The software does not configure an OS firewall or prove that another local service never forwards data.

隔离内网可在没有互联网时连接员工与内部模型，但与单台物理断网电脑是不同部署；必须按实际拓扑验证。软件不配置操作系统防火墙，也不能证明另一个本地服务绝不转发资料。

## 2. Connected preparation · 联网准备

Use a fresh checkout of a reviewed source revision with no private or untracked build inputs, a builder matching the target CPU/OS architecture, and trusted official dependencies. Review third-party/model licenses separately. Obtain required model files and container images in advance, including files a model server would otherwise download on first request. Do not copy personal caches or credentials wholesale.

使用经审查源码版本的全新 checkout，不混入私人或未跟踪的构建输入，并使用匹配目标 CPU/操作系统架构的构建机及可信官方依赖。单独审查第三方/模型许可。预先取得推理服务首次调用可能下载的全部文件与镜像；不要整包复制私人缓存或凭据。

From the repository root / 在仓库根目录：

```bash
# POSIX shell; requires Docker, Compose, Git, Make and sha256sum.
make install
make rust-test
make check
make test
make attacks
make verify
make build

REV=$(git rev-parse HEAD)
IMAGE="privacy-gateway:pilot-$REV"
mkdir -p offline-bundle
docker build --tag "$IMAGE" .
docker image inspect "$IMAGE" --format '{{.Id}}' > offline-bundle/image-id.txt
docker image inspect "$IMAGE" --format '{{.Os}}/{{.Architecture}}' > offline-bundle/platform.txt
printf '%s\n' "$REV" > offline-bundle/revision.txt
printf '%s\n' "$IMAGE" > offline-bundle/image-tag.txt
```

**Before exporting, test this exact image**, using the synthetic image smoke test in [CI](../.github/workflows/gateway.yml) and the manual checks in [deployment sections B–C](10-部署演练.md). Record the image ID, commands, environment and outcomes; a build alone is not validation. If a real model is required, separately test its actual image, weights and configuration. Fix failures before export.

**导出前验证这个确切镜像**：执行 [CI](../.github/workflows/gateway.yml) 中的合成镜像烟测及[部署演练 B–C](10-部署演练.md)。记录镜像 ID、命令、环境与结果，构建成功不等于验证成功；真实模型所需镜像、权重与配置须另验。失败后先修复再导出。

```bash
# Run only after the image's acceptance checks passed.
docker image save --output offline-bundle/gateway.tar "$IMAGE"
git archive --format=tar --output=offline-bundle/source.tar HEAD
(cd offline-bundle && sha256sum gateway.tar source.tar image-id.txt platform.txt revision.txt image-tag.txt > SHA256SUMS)
```

Transfer the bundle through an approved medium. Keep the expected checksums in a trusted independent record. Checksums detect changes but do not authenticate a maliciously replaced bundle and checksum list. Distribute the source/license notices alongside the image; model redistribution may need separate permission. Keep `.env`, keys, real prompts and enterprise data out of release assets. The build ignores `.env`; review every bundle's actual contents anyway.

通过批准介质转移，另以可信渠道保留预期摘要。摘要能发现修改，但不能认证同时被恶意替换的构件与摘要清单。随镜像提供源码与许可通知；模型再分发可能另需授权。发布资产不含 `.env`、密钥、真实提示及企业数据；即便构建已忽略 `.env`，也必须检查最终包。

## 3. Offline target · 离线目标机器

Preinstall the compatible Docker runtime and browser. Check free disk/RAM, CPU architecture and any model's hardware requirements. Do not assume an amd64 image works natively on arm64. This project currently promises no multi-architecture release matrix.

预装兼容 Docker 与浏览器，检查磁盘、内存、CPU 架构和模型硬件需求。不假定 amd64 镜像能在 arm64 原生运行；当前项目未承诺多架构发布矩阵。

```bash
cd offline-bundle
sha256sum --check SHA256SUMS
docker image load --input gateway.tar
IMAGE=$(cat image-tag.txt)
test "$(docker image inspect "$IMAGE" --format '{{.Id}}')" = "$(cat image-id.txt)"
mkdir source
tar -xf source.tar -C source
cd source
cp .env.example .env
# Edit .env: generate a fresh random GATEWAY_TOKEN of at least 32 characters.
# Keep CLOUD_ENABLED=false. For synthetic mode leave LOCAL_URL unset.
# Remove any CLOUD_URL, CLOUD_MODEL or CLOUD_API_KEY configuration.
chmod 600 .env

docker run --detach --pull=never --name privacy-gateway \
  --env-file .env --env HOST=0.0.0.0 --env CLOUD_ENABLED=false \
  --publish 127.0.0.1:3000:3000 \
  --read-only --tmpfs /tmp --cap-drop ALL \
  --security-opt no-new-privileges:true "$IMAGE"
```

Open http://127.0.0.1:3000 and enter your gateway token. Use synthetic input first. The explicit `--pull=never` prevents Docker from fetching a missing image. Do **not** use `make run` or `docker compose up --build` on an unprepared offline target: those commands build and may need external sources. Normal app operation does not auto-download a model.

打开 http://127.0.0.1:3000，输入网关 token，先用合成输入。`--pull=never` 防止 Docker 拉取缺少的镜像。不要在未准备的离线机器执行 `make run` 或 `docker compose up --build`，这些命令会构建并可能需要外部源。应用正常运行不自动下载模型。

For local inference, configure `LOCAL_URL`, `LOCAL_MODEL` and, where needed, an exact `LOCAL_ALLOWED_HOSTS` entry. Container `127.0.0.1` is the container itself, not the host. Use an administrator-reviewed container network or LAN address and its matching host allowlist; configure TLS/access control as appropriate. The full path must be a compatible `/v1/chat/completions` endpoint. No model server is started by the command above. See the [integration guide](07-本地隐私网关.md) for provider details. Stop and recreate the gateway to apply environment changes.

本地推理需设置 `LOCAL_URL`、`LOCAL_MODEL`，必要时配置精确的 `LOCAL_ALLOWED_HOSTS`。容器内 `127.0.0.1` 指容器自己，不是宿主。使用管理员审查过的容器网络或内网地址及匹配白名单，按需配置 TLS/访问控制；完整路径须为兼容的 `/v1/chat/completions`。上面的命令不会启动模型服务。供应商细节见[接入指南](07-本地隐私网关.md)。修改环境后需停止并重建网关容器。

## 4. Prove offline behavior · 验证离线行为

Record each result on the target. Do not upload real customer data for these checks.

在目标机器记录每项结果，不使用真实客户资料。

1. Deny external egress using the organization's approved network controls, including the model server and browser host. Keep only the local/LAN paths the chosen topology requires. Confirm with the network operator rather than assuming `CLOUD_ENABLED=false` is a firewall.
   由组织网络控制禁止外网，包括模型服务与浏览器宿主，只保留所需本机/内网路径；请网络负责人验证，不把关闭云配置当作防火墙。
2. Load the UI and inspect `Summarize alice@example.test` as unknown/local-only. Execute locally. Expect an explicitly synthetic result without a model, or actual inference only when a real local server is configured.
   加载界面，以未知/仅本地处理合成提示；未接模型应明确为合成结果，已接真模型才是推理。
3. Repeat the consumed request and wait beyond 120 seconds on a fresh request. Both stale operations must be refused; start a new inspection to continue.
   重放已消费请求，以及等待新请求超过 120 秒后再执行，都应拒绝；须重新检查。
4. Stop the local model, then inspect and execute a new request. Expect a clear error, not cloud fallback. Observe destination-only network telemetry without storing prompt bodies.
   停止本地模型，再检查并执行新请求，应明确报错而非回退云端。观察仅含目标的网络元数据，不保存正文。
5. Reboot/restart without external connectivity and repeat. Confirm no missing model files, license activation or first-use download is needed in the chosen third-party stack.
   在无外网条件下重启重试，确认所选第三方组件无需补下载、缺失文件或在线许可激活。

The gateway's own community license requires no online activation. This does not override Docker's or a model vendor's terms. Network observations are evidence for the tested environment, not universal privacy certification.

网关社区许可本身无需在线激活；这不改变 Docker 或模型供应商条款。网络观测仅证明所测环境，不是普遍隐私认证。

## 5. Release checklist · 发布清单

A pilot release must include a source revision, supported platform, image identity if an image is actually distributed, checksums, license files, installation instructions, rollback instructions and an accurate list of passed/failed/unrun checks. A source archive is not a prebuilt offline image.

试点发布应包括源码版本、支持平台、实际分发镜像的标识、摘要、许可、安装与回滚说明，以及准确的通过/失败/未运行清单。源码压缩包不等于预构建离线镜像。

- Publish only the exact artifact tested. A later rebuild must be revalidated even with the same tag.
- 只发布已测试的确切构件；同标签重建也要重验。
- Do not bundle credentials, real datasets or model weights without redistribution rights. Document third-party dependencies and preserve their notices.
- 不捆绑凭据、真实数据或无再分发权的模型权重；记录依赖并保留通知。
- Keep a previous verified bundle for rollback. Stop/remove only the gateway container, load the previous image, start with reviewed compatible configuration, then repeat synthetic checks. Request state is memory-only and cannot be restored.
- 保留上一已验证包。回滚仅停止/移除网关容器，加载旧镜像，以审查后的兼容配置重启并重做合成检查；内存请求状态不可恢复。
- Review [production acceptance](09-生产验收与运维.md) before customer data or multi-user deployment. A pilot release is not a security certification or an enterprise SLA.
- 使用客户数据或多用户部署前完成[生产验收](09-生产验收与运维.md)。试点版本不等于安全认证或企业 SLA。
