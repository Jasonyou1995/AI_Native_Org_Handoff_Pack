# 07 · 本地隐私网关

## 一次请求的完整流程

1. 浏览器把提示和可选文本附件交给本机网关。默认 `classification=unknown`、`mode=local_only`。
2. 网关合并文本，用规则和组织词表检查并生成本次随机占位符。原文与回填映射只存在网关内存；若配置本地分类器，检查阶段还会把原文发送给该受信任的本地模型。
3. 页面展示脱敏预览、发现类别及路由原因。未知或机密分类、仅本地模式、秘密格式、禁用云等条件阻止外发。`public` 是调用者声明，不是模型验证结论。
4. 本地处理使用原文。没有本地端点时仅返回明确标注的合成演示；失败不自动使用云端。
5. 只有选择 `hybrid`、声明 `public`、管理员启用云且规则允许时，才能人工检查全部预览并批准固定 payload hash。
6. 使用短期单次 receipt（批准凭据）调用云端。云端收到脱敏文本；返回后只恢复本请求的已知占位符。结果仍需用户核对。

每次请求有效期 120 秒，内存最多保存 100 个待处理请求。执行会消费请求，批准和云调用不能重复使用。过期或重启后重新检查，不保留历史会话。过期状态在后续操作中惰性清理，不宣称定时物理擦除。

## 配置表

在 `.env` 中修改非秘密配置；生产凭据由部署平台注入。修改后重建/重启服务，旧请求和批准会失效。

| 环境变量 | 默认/要求 |
|---|---|
| `HOST` | 应用默认 `127.0.0.1`；Compose 设为容器内 `0.0.0.0`，只向宿主 `127.0.0.1:3000` 映射 |
| `PORT` | `3000`；若改变须同时调整容器端口映射 |
| `GATEWAY_TOKEN` | Compose 必填；非 loopback 绑定要求至少 32 字符。使用随机值，不沿用示例 |
| `LOCAL_URL` | 不设则合成演示；必须是完整 Chat Completions URL，不是仅 `/v1` |
| `LOCAL_MODEL` / `LOCAL_API_KEY` | 配置本地端点时必须设模型，认证 key 按端点需要提供 |
| `LOCAL_ALLOWED_HOSTS` | 逗号分隔精确主机名，额外放行管理员控制的私网/容器模型；默认仅 loopback |
| `PRIVACY_SCANNER` | 默认 Rust；仅显式设为 `typescript` 使用 TypeScript 扫描器，不是故障自动回退 |
| `PRIVACY_SCANNER_BIN` | 可选管理员控制的 Rust 可执行路径；默认 `rust-core/target/release/privacy-scanner` |
| `CLASSIFIER_MODEL` | 可选；要求已配置 `LOCAL_URL`，使用同一 URL 和 key、此处指定的模型执行保守分类 |
| `CLOUD_ENABLED` | 仅精确值 `true` 开启，默认关闭 |
| `CLOUD_URL` | 完整 HTTPS Chat Completions URL；不接受 URL 内用户名、密码、查询或片段 |
| `CLOUD_MODEL` / `CLOUD_API_KEY` | 配置云端点时必须设模型；凭据按供应商要求提供 |
| `ORG_TERMS` | 逗号分隔组织敏感词，最多 100 个，每个最多 100 字符；不是完整语义分类器 |

本地额外主机白名单不是私网地址证明，也不防 DNS 变化、管理员错误配置或本地模型转发。只放行你实际控制和审核的服务，不能把公网端点命名为“本地”以绕过审批。

## 接入已有 Ollama / vLLM

先由管理员安装、审查并启动模型服务，选择获准使用且硬件可运行的权重，记录权重版本、许可证和服务配置。本仓库不自动拉模型、不自动安装推理框架，也不打包模型权重。

网关仅使用非流式 `POST`，请求包含 `model`、文本 `messages`、`stream:false`、`max_tokens:2048`、`temperature:0`，读取 `choices[0].message.content`。超时 15 秒，响应体最多 128 KiB，响应文本最多 65,536 字符。端点必须支持这些参数和文本响应；厂商独有鉴权、Responses API、工具调用、图像、流式接口不属于当前适配范围。

Ollama 提供部分 OpenAI API 兼容能力，vLLM 提供兼容服务器；具体模型仍须具备正确的 chat template 并逐项联调。[Ollama 官方兼容文档](https://docs.ollama.com/api/openai-compatibility)、[vLLM 官方服务文档](https://docs.vllm.ai/en/stable/serving/openai_compatible_server/)

### Docker Desktop 中连接宿主的现有本地模型

确保模型仅在受控网络监听，且已禁用云模型/远端转发。`localhost` 在容器内不是宿主机；Docker Desktop 可使用 `host.docker.internal` 访问宿主服务。[Docker 官方 host-gateway 说明](https://docs.docker.com/reference/cli/docker/container/run/#add-entries-to-container-hosts-file---add-host)

Ollama 对应 `.env` 示例，替换模型名为你已经安装并获准使用的模型：

```dotenv
LOCAL_ALLOWED_HOSTS=host.docker.internal
LOCAL_URL=http://host.docker.internal:11434/v1/chat/completions
LOCAL_MODEL=your-approved-installed-model
CLOUD_ENABLED=false
```

若现有 vLLM 服务监听宿主 8000 端口，改为：

```dotenv
LOCAL_ALLOWED_HOSTS=host.docker.internal
LOCAL_URL=http://host.docker.internal:8000/v1/chat/completions
LOCAL_MODEL=your-served-model-name
CLOUD_ENABLED=false
```

宿主服务须能接收容器网络请求。不要为方便直接对公网开放模型端口。Linux Engine 不一定内建上述名称；管理员可在 Compose 的 `gateway` 服务加入 `extra_hosts: ["host.docker.internal:host-gateway"]` 并核实宿主监听/防火墙，或在同一个受控 Docker 网络使用模型服务名。模型名为 `model` 时，白名单填 `model`，URL 可为 `http://model:8000/v1/chat/completions`。这些是部署模板，不表示已在你的硬件或模型上验证。

### 同一 Linux 主机的 loopback 接法

已有模型只监听宿主 loopback 时，可使用 Linux Docker host network 的明确部署方式，避免误把容器 loopback 当宿主。host network 取消网络隔离和端口映射，不适用于未经审核的共享宿主。[Docker host network 文档](https://docs.docker.com/engine/network/drivers/host/)

```bash
docker compose down
docker build -t privacy-gateway:pilot .
# Set LOCAL_URL to http://127.0.0.1:11434/v1/chat/completions in .env.
docker run --rm --network host --env-file .env \
  -e HOST=127.0.0.1 --read-only --tmpfs /tmp \
  --cap-drop ALL --security-opt no-new-privileges:true \
  privacy-gateway:pilot
```

### 任意地区的云服务

管理员填入经审查的 HTTPS 端点、模型名和运行时 key，设 `CLOUD_ENABLED=true`，重启。每次请求仍须 `hybrid + public + 规则允许 + 人工批准`，启用不等于自动外发。不自动发现提供商、不绕过地区限制。兼容协议不代表许可证、地区可用性、出口规定、数据处理条款或保留政策相同；用户/企业必须分别核对。

### 本地分类模型和微调

规则及词表始终执行。可选 `CLASSIFIER_MODEL` 在**检查阶段**把原文发送到 `LOCAL_URL`，使用相同凭据但指定分类模型。模型必须返回严格 JSON：`{"decision":"local"}` 或 `{"decision":"review"}`。返回 `local`、格式不符、超时或错误都会否决外发；`review` 只表示继续人工审查，不能覆盖未知/机密/秘密等硬性阻断，也不能自动批准。

```dotenv
CLASSIFIER_MODEL=your-approved-local-classifier
```

该配置要求相同本地端点能按模型名路由到已部署模型。如果模型服务只提供单一模型，须使用其实际服务名或另行部署经审查的本地模型路由层。`/api/status` 的 `classifier` 为 `local_advisory` 或 `disabled`；这是配置状态，不是准确率证明。

已经微调的模型可通过上述服务协议接入，但本仓库不训练、不微调、不提供已验证的隐私分类权重。通用模型未必按要求输出 JSON，也可能漏判，必须用客户授权语料单独评估。分类器和生成模型都属于原文可见的受信任处理边界，其日志与网络行为要纳入治理。

## API：先合成数据，再真实集成

以下需系统已有 `curl`，手动替换标记值。不要将真实 token 写进脚本或提交；由当前 shell 安全注入 `GATEWAY_TOKEN`。

```bash
curl -sS http://127.0.0.1:3000/api/status \
  -H "Authorization: Bearer $GATEWAY_TOKEN"

curl -sS http://127.0.0.1:3000/api/inspect \
  -H "Authorization: Bearer $GATEWAY_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"Summarize alice@example.test","classification":"unknown","mode":"local_only","files":[]}'
```

返回 `requestId`、`route`、`reasons`、`findings`、`redactedPreview`、`outboundPayload`（完整外发请求体）、`destination`（目标 URL 与模型）、`payloadHash`、`expiresAt` 等。复制 `requestId` 后在有效期内调用：

```bash
curl -sS http://127.0.0.1:3000/api/local \
  -H "Authorization: Bearer $GATEWAY_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"requestId":"REPLACE_WITH_REQUEST_ID"}'
```

云端流程必须重新检查 `mode:"hybrid", classification:"public"` 的合成请求。**先人工阅读完整 `outboundPayload` 和 `destination`，确认系统提示、正文、模型参数、供应商目标均获准外发**，再使用该次返回的值：

```bash
curl -sS http://127.0.0.1:3000/api/approve \
  -H "Authorization: Bearer $GATEWAY_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"requestId":"REPLACE_WITH_REQUEST_ID","payloadHash":"REPLACE_WITH_PAYLOAD_HASH"}'

curl -sS http://127.0.0.1:3000/api/cloud \
  -H "Authorization: Bearer $GATEWAY_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"receipt":"REPLACE_WITH_RECEIPT"}'
```

`/api/approve` 是客户端表达批准的接口，不是能证明真人阅读的机制。不要自动串联批准步骤。API 调用方必须自行保留人审交互；服务端没有组织级审批工作流或个人签名。

API 最多 4 个文件，当前浏览器界面更保守地最多 3 个，提示输入上限 16,000 字符；API 提示上限 32,768 字符，合并文本仍受 64 KiB 字节限额约束。

文件以 `files:[{"name":"sample.txt","content":"Synthetic text"}]` 发送，文件名不加入模型正文。只接受文本扩展名，不等于安全支持所有同名文件。没有 OCR、PDF、Office、压缩包解析或隐藏元数据清除。勿将二进制改名骗过文件类型检查。

## Python 集成示例，无额外依赖

`examples/python_client.py` 使用 Python 3 标准库 `urllib`，只带内置合成文本，不读取真实文件。默认检查后执行本地处理，不会自动批准云请求。示例本身适用 Apache-2.0，允许包括商业使用在内的该许可用途；转售网关核心、收费提供其访问或托管、商业捆绑核心仍按 Community 许可另行授权。调用 API 不会自动改变示例或独立插件的权属。

The example itself is Apache-2.0, including permitted commercial use. Separate licensing applies to commercializing the Community-licensed gateway core, not merely to using this example or independently calling a public API.

网关启动后，在另一个终端安全注入 `GATEWAY_TOKEN`，可选设置 `GATEWAY_URL`（默认 `http://127.0.0.1:3000`，示例只接受 loopback origin）：

```bash
python3 examples/python_client.py
python3 examples/python_client.py --with-file
```

`--with-file` 加入内存中的虚构 `synthetic.txt`，不在磁盘落文件。客户端禁用代理继承与 HTTP 重定向，单次网络调用超时 30 秒，响应最多 256 KiB，不自动重试、不输出 token 或 receipt、不将批准状态写盘。模型结果会显示在终端，所以本示例坚持只用合成数据。

云配置及授权就绪后，可显式选择人工审查流程：

```bash
python3 examples/python_client.py --review-cloud --with-file
```

仅在交互终端运行。它展示完整外发 JSON 与目标，要求人工输入 `SEND` 才调用批准和发送；其他输入取消。没有自动确认标志，非交互 stdin 直接拒绝。若策略不允许云端，不发送也不自动改走其他路径。输入确认时过期则重新检查，不能复用旧批准。

## Rust 扫描边界

默认检测通过本机子进程调用 Rust 核心，原文经 stdin 进入，返回类别、阻断标志和 UTF-16 区间，不将映射交给子进程。桥接器校验响应，超时 5 秒或缺失/非法输出则失败关闭。它不是网络服务；操作系统仍可观察子进程内存及管道。`/api/status` 的 `scanner.available` 只检查可执行文件可访问，不是安全认证或模型健康检查。

管理员可显式设置 `PRIVACY_SCANNER=typescript` 运行兼容模式。该选择应记录在验收结果，重新验证检测语料；不能在 Rust 错误后悄悄改配置继续外发。构建细节见 [Rust 核心说明](../rust-core/README.md)。
