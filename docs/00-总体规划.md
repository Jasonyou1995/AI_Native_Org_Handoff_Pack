# 00 · 总体规划

> 一句话故事：我们把一个只写了文档的 agent 交接中间件，变成一台能跑的实验仪器，用它回答"结构化交接到底省不省钱"，同时给社区留下一个可复现的协同成本基准。

读完第一段就能懂全局，细节在 01 到 05 各文档。

## 为什么做

### 现状

本仓库（改名 `handoffpack`）现在只有文档，**零行源代码**。

已经有的：`spec/HANDOFF-PACK-SPEC.md` 定义了交接包本体。SBAR 四段式（Situation / Background / Assessment / Recommendation，医院交班格式）+ 能力令牌（capability token，HMAC 链式签名，scope 只能缩不能扩）+ 硬过期 + 撤销句柄 + 6 态生命周期 + 10 条验收场景。

缺的：三样。

| 缺什么 | 后果 |
|---|---|
| 实验层：几百个 agent 员工的组织模拟器 + 对照实验 | 只能讲道理，无法证明 |
| 理论层：协同成本的成分分解与机制解释 | 只能测 token，测不到机制 |
| 传播层：论文 + 可复现工件 + 分工 | 单人不可持续 |

### 范式依据

夏威夷大学那篇 PDF 是 **HICSS 2025《Simulating Market Equilibrium with Large Language Models》**（Enric Junqué de Fortuny, IESE）。

它确立了本项目的做法：先造工程系统，再用系统跑实验。关键手法有三条，我们全部照抄。

| 手法 | 原文怎么做 | 我们怎么做 |
|---|---|---|
| 给 agent 配备 oracle 工具 | 让它算，而不是让它猜，避免幻觉 | T1 博弈任务配解析最优解查询工具 |
| 用已知理论最优解当 ground truth | 度量"最终价格与理论最优价的距离" | T1 度量偏离度，T2 用单元测试 |
| 跑上万次并扫温度 | 8,000 次模拟，找稳定工作区间 | 主网格上千次 run，锁定模型快照与温度 |

唯一改动：因变量从**博弈均衡收敛**换成**协同成本**。

### 学术新颖性（已查重）

**CS 侧已经做过的：**

| 工作 | 结论 |
|---|---|
| PACT（action-state communication） | 三字段结构化消息让 token 从约 480 降到约 40，长度约 10 倍 |
| MASBench（部分可观测下的多智能体协作） | 加 Protocol 层后 token 从 3,531 降到 1,851，分数反而上升 |
| Routed Graph Handoff | 类型化依赖图压缩 2 到 3 倍，加路由器后各项基准提升 8 到 13 个百分点 |

它们测的是两样东西：**token 数**和**任务成功率**。

**管理学侧完全没有的：**

1. 没有人用交易成本理论（Williamson）把协同成本**分解成分**。
2. 没有人区分"结构"和"承诺"两种机制，也没有做过它们的**交叉**。
3. 没有人在**数百 agent 的组织规模**上做统计推断。
4. 没有预注册。

**我们的位置**：CS 论文说"结构化省 token"。我们说：

> **结构省的是搜索成本，承诺省的是事后返工成本。两者会交叉。在数百 agent 的组织规模上，结构化的收益超线性增长。**

这就是 IS/OM 顶刊要的那一篇。

## 理论模型

```
                      智能体中介的组织
                             │
                    ┌────────┴────────┐
              消息设计              组织环境
     ┌───────────┼───────────┐      ┌────┴─────┐
     F 自由文本  S 结构化      C 契约  拓扑    规模N
     （隐含）    （声明）      （声明+强制） chain  8
     （口头）    （工单）      （合同）  tree  32
                               ↑  hub-and-spoke  96
                    唯一变化轴：强制力                  mesh
                    （不是啰嗦程度）
                             │
        ┌────────────┬───────┴───────┬────────────┐
    C_search      C_spec         C_coord       C_adapt
   搜索与解析     表达与转述      事中协调      事后适应
        │            │               │            │
   澄清轮次      上下游token     交接时延     verify失败
   重复约束率     消息字节数      阻塞时长     越界动作
   首次理解率     消息条数        交接深度     返工轮数
   未解析字段数                    │          撤销/重放
        │            │               │            │
        └────────────┴───────┬───────┴────────────┘
                             │
                   协同成本 = 四项之和
              （token / 美元 / 墙钟秒 三种货币同时报告）
                             │
                   质量 Q 单独追踪，不并入成本
                             │
                   主指标：cost_per_success
```

**关键机制**：结构（S 相对 F）打的是 `C_search` 和 `C_spec`。承诺（C 相对 S）打的是 `C_adapt`。它们的代价都落在 `C_spec` 里。所以净效应必须看每成功任务的总成本，不能看单条消息。

## 五条假设

| 编号 | 假设 | 中介机制 |
|---|---|---|
| **H1** | 结构显著降低 `C_search` 与 `C_spec`。主对比是 **`S` 相对 `F`**（只变声明，不变强制）；`C` 相对 `F` 作为扩展对比报告，因为 `C` 还叠加了强制 | 远距离知识必须显式编码，否则接收方要自己推断 |
| **H2** | 承诺（`C-shadow` 相对 `S`）显著降低 `C_adapt`；在低争议任务上不显著 | 声明义务本身就是信号，不需要靠强制也能减少事后返工 |
| **H3** | **交叉效应**：承诺的边际收益随**任务不确定性 U** 上升而增大，在低不确定性任务上为**负**（过度契约） | 契约有固定成本，要够不确定才划算。U 按 `T0` 低、`T1` 中、`T2` 中、`T3` 高赋值，与 `docs/03` 的编码一致 |
| **H4** | C 的上游成本上升，但 `cost_per_success` 仍下降 | 成本是转移，不是消失 |
| **H5** | **规模效应**：agent 数 N 上升时，结构化收益**超线性**增长。判据写死为：log-log 模型 `log(cost_per_success) ~ log(N) + D + D:log(N)` 中，**`β(D:log N) < 0`**（结构化臂的成本弹性低于自由文本臂），且 cluster-bootstrap CI 不含 0 | 信息在组织层级里衰减，人数越多越需要显式编码 |

## 已拍板的决策

| 决策 | 选定 | 为什么 |
|---|---|---|
| 人类基线 | **小规模 pilot，N≈12** | 生态效度够用，简易知情同意即可，不走正式 IRB，不拖排期 |
| 主力模型 | **frontier API** | 强、快、省掉 GPU 采购。代价是必须配成本闸门与可复现性护甲 |
| 仓库名 | **`handoffpack`** | 下划线大写名对 npm、GitHub 搜索、星标增长都不利。现在仅 1 星，改名零成本 |
| 私有论文仓 | `~/Documents/GitHub/_private/handoff-paper/` | 遵守 `AGENTS.md` 的 IP 边界 |
| 主网格预算 | **未决** | 校准 pilot 跑完后拿实测单价回来确认 |
| **H2 的测法** | **加 `C-shadow` 探针臂作机制子研究** | 强制生效时越界动作根本不会发生，返工成本因此按构造归零，H2 会变成循环论证。子研究只在 T2、chain 与 hub-and-spoke、N 取 8 与 32 上跑，不进主网格，约 80 个 run，对主网格 825 个 run 的增量约 10% |
| **arXiv 与 IS 双盲冲突** | **默认选项 1，2026-12 前拍板** | 预印本公开即锁定作者。这不是工程能解决的问题，必须查 CIST 与 ICIS 当年的预印本政策后由 Jason 定 |
| **数字冻结里程碑** | **2027-02-20** | 预印本目标 02-26，早于 P4 退出日 03-15 约两周。数字先冻结，之后只改文字与图 |

## 风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 审稿人攻击"结构化赢在信息更多" | 论文被拒，致命 | `renderToProse()` 机械降级，保证三臂零信息差；跑字段覆盖审计；token 数对照 |
| 审稿人攻击"agent 员工行为不像真人" | 生态效度被质疑 | N≈12 人类基线 pilot；如实报告局限 |
| 成本失控 | 预算超支 | `--max-spend` 硬停；先跑 N≈5 校准 pilot 反推规模；响应全量落盘让分析零成本 |
| 模型漂移，结论不可复现 | 复现失败 | 锁快照 ID；全量 transcript；开源 5% 可复现子集；收尾跑漂移探针写进 Threats to Validity |
| ground truth 不可靠（T3） | 结论建立在流沙上 | T3 只用 rubric + 人工校准子样本；结论不依赖 T3 单臂 |
| 旧计划缺陷漏改 | 工程跑不起来 | 11 条逐行核实后写进 `01-工程计划.md`，每条带 file:line、可观察症状与退出条件 |
| 多人改同一文件 | 合并冲突，返工 | 每个目录单一 owner；主分支禁止直推；每周五 Demo Day 当集成测试 |
| 技能供应链投毒 | 引入恶意指令 | 只装点名技能；装完人工读 SKILL.md；36% 检出注入率不是开玩笑 |
| 本机网络封锁 GitHub | 技能装不上 | 已知阻塞，不阻塞主线；换环境或授权后补装 |
| `gh` 登录失效 | P5 全线停摆 | 需 Jason 跑 `gh auth refresh -h github.com` |
